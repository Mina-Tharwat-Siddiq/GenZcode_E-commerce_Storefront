# GenZcode E-commerce Storefront

واجهة متجر إلكتروني كاملة مبنية بـ React + Vite، تم تصميمها لتغطي أغلب احتياجات متجر حديث: تصفّح المنتجات، تفاصيل المنتج، السلة، المفضلة، الحسابات الشخصية، ولوحة تحكم للإدارة. أدناه شرح مفصّل لكل قسم من المشروع وكيفية تشغيله وتطويره.

---

## 1. نظرة عامة على البنية

```
src/
├── api.js                    // تهيئة axios للتعامل مع DummyJSON API
├── App.jsx                   // تعريف جميع المسارات (Routes) وحماياتها
├── context/                  // مزوّدات الحالة المشتركة (Auth، Cart، Wishlist ...)
├── components/               // أجزاء الواجهة العامة (Header، Footer، بطاقات المنتجات...)
├── pages/                    // الصفحات الكاملة (Home، Login، Signup، Product Details ...)
└── assets/                   // الصور والأيقونات الثابتة
```

---

## 2. شرح الصفحات الرئيسية

### 2.1 Home (`src/pages/Home.jsx`)
- ترويسة (Hero) مع دعوة لاتخاذ إجراء.
- تصنيفات وأقسام مميزة (Best Selling، Featured ...).
- تستخدم `ProductsContext` لجلب المنتجات من DummyJSON (فئات الأزياء).
- بطاقات المنتجات (`ProductCard`) تعرض حالة المخزون وزرًا سريعًا للإضافة للسلة/المفضلة.

### 2.2 Product Details (`src/pages/ProductDetailsPage.jsx`)
- عرض صور المنتج مع معرض مصغرات.
- اختيار اللون، المقاس، الكمية، زر الإضافة للسلة والمفضلة.
- تبويبات: الوصف / التقييمات (Reviews) مع إمكانية إضافة مراجعة جديدة.
- قسم منتجات مرتبطة (You might also like).

### 2.3 Login & Signup
- `LoginPage.jsx`: تسجيل الدخول للمستخدمين أو الأدمن. تعرض رابطًا للتوجّه لصفحة التسجيل.
- `SignupPage.jsx`: إنشاء حساب جديد، وبعد تقديم النموذج يتم إنشاء مستخدم محلي وتسجيل الدخول تلقائيًا.
- كلا الصفحتين تمتلكان نفس التصميم (Header، بطاقات، Footer) حسب الهوية البصرية.

### 2.4 My Account (`src/pages/MyAccount/*`)
- صفحات فرعية داخل `/my-account`: الطلبات، المفضلة، العناوين، كلمة المرور، التفاصيل الشخصية، تسجيل الخروج.
- الوصول إليها يتطلب تسجيل الدخول (`RequireAuth`).

### 2.5 صفحات أخرى
- About، Contact، Search، Cart، Checkout، NotFound، Unauthorized.
- لوحة التحكم للإدارة ضمن `/AdminDashboard` (منتجات، طلبات، عملاء، مراجعات). تتطلب دور "admin".

## 3. السياق (Context) وإدارة الحالة

### 3.1 AuthContext
- يدير تسجيل الدخول/الخروج والاشتراك.
- يدعم مستخدمين ثابتين (LOCAL_USERS) بالإضافة إلى المستخدمين المسجلين من الواجهة (يحفظون في `registered_users` داخل localStorage).
- `register`:
  - يتحقق من المدخلات وتفرد البريد/اسم المستخدم.
  - يحفظ المستخدم الجديد ويقوم بتسجيله مباشرة.
  - يستخدم `toast` لعرض رسائل النجاح/الأخطاء.
- `login`:
  - يحاول أولًا مقارنة الـ LOCAL_USERS + registered_users.
  - إذا لم يجد، يجرب DummyJSON API.
- `logout`: يحذف بيانات المستخدم ويعيد التوجيه إلى `/login`.

### 3.2 CartContext
- يخزن عناصر السلة في localStorage (`cart_items`).
- دوال: `addToCart`, `removeFromCart`, `updateQuantity`, `getTotalItems`, `getTotalPrice`، إلخ.
- قبل أي عملية إضافة للسلة يتم التأكد من تسجيل الدخول (`ensureAuthenticated`): إذا لم يكن هناك مستخدم يتم إظهار Toast وتحويله إلى `/login`.

### 3.3 WishlistContext
- مشابه للسلة لكن لعناصر المفضلة (`user_wishlist` في localStorage).
- `addToWishlist` يتأكد من تسجيل الدخول بنفس منطق `ensureAuthenticated`.

### 3.4 سياقات أخرى
- `ProductsContext`: يجلب منتجات الملابس من DummyJSON ويطبق Pagination بسيط محليًا.
- `ReviewsContext`: يجمع مراجعات المنتجات من DummyJSON ويعرضها في لوحة التحكم.
- `Theme/Orders/Customers` ... إلخ (بحسب الحاجة).

## 4. المكوّنات العامة

### Header & Footer
- `Header.jsx`:
  - شريط علوي للعرض الترويجي.
  - روابط للتنقل وقائمة منسدلة للتصنيفات.
  - مربع بحث، أيقونة السلة (مع عدّاد العناصر)، وأيقونة المستخدم.
  - عند تسجيل الدخول يظهر اسم المستخدم بجانب الأيقونة ويؤدي إلى `/my-account/orders`. أما في حال عدم وجود مستخدم فينتقل إلى `/login`.
- `Footer.jsx`: يحتوي أقسام الدعم، الشركة، التسوق وروابط وسائل التواصل.

### ProductCard
- صورة بخلفية دافئة (#F1AE60)، زر سريع للسلة، زر مفضلة (قلب).
- حالة المخزون تظهر أعلى البطاقة.
- العنوان والسعر مع مساحة لعرض حالة المخزون مرة أخرى والسعر بالأسفل.

### Newsletter, Hero, Sections
- مكوّنات داعمة للصفحة الرئيسية تحتوي عناوين وأزرار CTA (تستخدم اللون البرتقالي الموحد).

## 5. التصميم الهوية البصرية
- **الخط**: Roboto (تم استيراده عالميًا عبر Google Fonts).
- **اللون الرئيسي**: `#F1AE60` (تم تعيينه في `:root` لاستخدامه كـ brand primary).
- يتم إعادة تلوين جميع أزرار Bootstrap الافتراضية إلى اللون البرتقالي، بما في ذلك الحواف والنصوص وروابط `.btn-link`.
- خلفيات Hero وFooter وأجزاء أخرى تستخدم نفس اللون لتوحيد الهوية.

## 6. الحماية والتنقل

### Route Guards (`App.jsx`)
- `RequireAuth`:
  - يقرأ `user_auth` من localStorage.
  - إذا لا يوجد، يعيد التوجيه إلى `/login`.
- `RequireAdmin`:
  - يتحقق أن المستخدم الحالي دوره "admin"، وإلا يعيد التوجيه إلى `/unauthorized`.
- المسار `/` أصبح عامًّا ويعرض الصفحة الرئيسية بدون طلب تسجيل دخول، بينما صفحات My Account وCheckout وغيرها ما زالت محمية.

### سلوك الأزرار
- أي عدد من الأزرار الرئيسية (Add to Cart, Wishlist) تستخدم دوال السياقات التي تكشف حالة تسجيل الدخول وتحوّل المستخدم إلى صفحة الدخول عند الحاجة.

## 7. خطوات التشغيل والتطوير

1. **تثبيت الاعتمادات**  
   ```bash
   npm install
   ```

2. **تشغيل الخادم المحلي**  
   ```bash
   npm run dev
   ```
   ستجد الرابط (عادة `http://localhost:5173` أو المنفذ التالي المتاح).

3. **البناء للإنتاج (اختياري)**  
   ```bash
   npm run build
   npm run preview   # لمعاينة نسخة الإنتاج
   ```

> ملاحظة: Vite قد يختار منفذًا آخر إذا كان 5173 مشغولًا (يظهر في الطرفية).

## 10. خلاصة

المشروع يوفر نموذجًا متكاملًا لمتجر إلكتروني مع تجربة مستخدم حديثة، المصادقة (Login/Signup)، إدارة السلة والمفضلة، صفحات حساب العميل، ولوحة إدارة. يعتمد على سياقات React لتقليل التعقيد وتسهيل مشاركة الحالة، ويستخدم DummyJSON كمصدر بيانات تجريبي مع إمكانية التبديل لخدمات حقيقية بسهولة.

يمكنك البدء فورًا بتشغيل `npm run dev` واستكشاف الصفحات، ثم البناء عليها أو تخصيص الهوية البصرية حسب متطلباتك. بالتوفيق في تطوير المتجر! 🎉
